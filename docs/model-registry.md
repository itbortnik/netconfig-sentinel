# Реестр экспериментальных моделей

Isolation Forest подключён к постоянному API и UI только по явному выбору.
Это контрольный детектор на 33 структурированных признаках, не production-модель
и не доказательство безопасности сети. Transformer и Batfish этим путём не запускаются.

## Обучение и выбор

Перед обновлением работающей установки сохраните проверенную резервную копию БД
и ключ шифрования, затем выполните `python -m app.db.migrate` с прежними настройками.
Миграция `0002_model_registry` добавляет таблицу `models`, не переписывает старую
историю и не меняет ключ. Без миграции новый API возвращает schema-unavailable.
Автоматического создания схемы при startup и destructive downgrade нет.

Все операции требуют текущий service bearer-token:

| Операция | Путь |
| --- | --- |
| Обучить и сохранить новый forest | `POST /api/v1/models/isolation-forest` |
| Паспорта моделей от новых к старым | `GET /api/v1/models?limit=20&offset=0` |
| Паспорт конкретной модели | `GET /api/v1/models/{model_id}` |

POST принимает `configuration_ids`: 8–100 UUID **сохранённых** снимков, и необязательный
`contamination` в диапазоне `(0, 0.5]`, по умолчанию 0.1. UUID в таком запросе — не
вымышленные примеры и не пути файлов. Обучающие снимки должны быть полностью разобраны,
иметь hostname и три явно заданные inventory-метки. Группа по vendor, platform,
device_role, site_class и service_profile одна; UUID устройств, hostname и исходные
hashes различны. Несколько версий/копий одного устройства не увеличивают размер группы.
Это проверка входных идентификаторов, не удостоверение физических устройств или сетей.

Бюджет запроса 16 KiB; суммарный канонический JSON обучающей группы ограничен 16 MiB.
Seed фиксирован на 42, деревьев 200, обучение использует один worker. На процесс
разрешено одно обучение одновременно; второй запрос получает 429 с Retry-After.
Глобальной квоты между процессами, очереди, отмены и rate-limit пока нет.

API возвращает неизменяемый паспорт `model-registry-0.1.0`: model_id, время,
статус `experimental`, SHA-256 числового артефакта, decision_offset, версию алгоритма,
scikit-learn и feature schema, параметры, статистики и полный список обучающих
снимков с UUID/hash/timestamps/hostname. Нет статуса approved, автоматического
выбора лучшей модели или вымышленных метрик качества. Contamination — настройка
алгоритма, не измеренная доля нарушений.

Для анализа передайте в обычный POST `/api/v1/configurations/{id}/analyze` поле
`statistical_model_id` с UUID сохранённой модели. Его можно сочетать с эталоном/peers.
Группа должна совпадать, целевой снимок полностью разобран. Устройство, hostname
и source hash цели исключены из обучения; обучающие снимки не новее целевого по
времени приёма API. Это не подтверждённое время съёма с оборудования и не независимый
chronological backtest. Модель можно явно обучить позднее для анализа старого снимка,
если сами обучающие снимки удовлетворяют этому ограничению.

Неверные/отсутствующие входы дают общий 400 и не создают модель/анализ или успешный
audit-event. Отсутствующая модель не заменяется незаметно policy-only анализом.
GET неизвестного UUID — 404. Повреждённое хранилище — общий 503.

## Хранение без исполняемых объектов

Модель сохраняется как ограниченный JSON `numeric-isolation-forest-0.1.0`:
числовые splits, children, samples, threshold и offset. Проверяются связность,
единственный родитель, отсутствие циклов/неверных индексов, finite values,
глубина до 8, до 511 узлов на дерево, до 200 деревьев и согласованность metadata.
Нет pickle/joblib, импорта классов из артефакта или endpoint загрузки внешней модели.
Риски загрузки исполняемых Python-объектов описаны в
[документации scikit-learn](https://scikit-learn.org/stable/model_persistence.html).

При обучении числовой scorer сверяется с fitted estimator на обучающих векторах;
unit tests дополнительно проверяют постоянные/случайные векторы, реальные splits,
float32 threshold boundaries и классификацию при нулевом decision. Вычисление сохраняет
порядок накопления глубин; повторного fit при GET, анализе или перезапуске нет.
Связь score/offset/decision соответствует
[контракту IsolationForest](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html).

Артефакт и паспорт вместе находятся в аутентифицированном зашифрованном envelope,
привязанном к типу `model` и UUID. При чтении проверяются SHA-256 и согласованность
паспорта с деревьями. UUID, artifact hash и timestamp открыты в таблице; hostname,
обучающая группа и числовые деревья закрыты внутри payload. Запись модели и
`model.trained` атомарны: ошибка аудита откатывает модель. Через API нет изменения
или удаления модели.

## Результат и интерфейс

Версия `analysis-api-0.3.0` сохраняет паспорт модели, score_samples,
decision_function и prediction в `statistical`. Если prediction = -1,
сохраняется одна статистическая находка с model_id/artifact hash и объяснение,
проверенное повторным scoring той же модели. Диагностические отклонения от медиан
не являются причинными объяснениями или tree attribution.

В risk включён только фактически выполненный statistical detector. Отсутствие
выброса — completed с нулевым сигналом, не unavailable. Веса нормализуются по
выполненным policy/peer/statistical источникам; policy guardrails сохраняются,
различия с эталоном остаются вне риска. Старые анализы 0.1/0.2 читаются без повторного fit.

В UI заполните inventory, сохраните снимки разных устройств и нажимайте
«Добавить в обучение модели». В реестре выполните «Обучить и сохранить модель»,
затем отдельно «Выбрать модель». После этого выберите целевой снимок и анализируйте.
Паспорт и фактический статистический результат доступны в раскрываемых секциях.
Выбор/обучающие снимки очищаются при logout/reload; сохранённые модели и история
остаются в БД. После таймаута сначала проверьте реестр/историю, прежде чем повторять POST.

Функциональные проверки и минимальный размер 8 не подтверждают качество детекции.
Нужны разрешённые реальные данные, независимая оценка, калибровка порога и
контроль дрейфа. Этот registry не регистрирует Transformer checkpoints и не
предоставляет promotion, rollback, retention или deployment approval.
