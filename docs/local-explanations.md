# Локальные объяснения находок

Модуль `app.explanation.local` предоставляет детерминированное объяснение
для `policy_engine`, `expected_configuration` и `peer_baseline`. Используется локальный
версионированный каталог политик; LLM и поиск RAG пока не подключены.

Перед объяснением находка сравнивается с результатом повторного запуска
детектора. Для эталонного отклонения необходимо передать выбранный
`ExpectedConfiguration`; для peer-находки — фактически использованный `PeerBaseline`.
Изменённые значения, оценки, ссылки или рекомендации
в находке приводят к отказу. Устаревшая версия каталога также отклоняется.
Для отсутствующего параметра та же находка может относиться к нескольким
текстам: объяснение связывается с hash конкретного переданного снимка.

Контракт `FindingExplanation` сохраняет severity, confidence, anomaly_score,
ID и версию детектора. SHA-256 полного Finding связывает объяснение с его
значениями. Источники представлены hash снимка, номерами строк и hash исходного
оператора; сырой текст в объяснение не копируется. Для отсутствующих параметров
строки не выдумываются. Неполный разбор явно отражается в ограничениях.

Название, пояснение и рекомендация для политик берутся из утверждённого
каталога кода, а не из текста конфигурации. Для эталона применяется общее
объяснение сравнения canonical-фактов. Observed/expected остаются в исходной
находке. Ссылки — идентификаторы внутренних документов; содержимое документов
не загружалось и не считается независимо проверенным. Это первый локальный
режим деградации для будущего слоя LLM/RAG, не реализация генеративного провайдера.

`formal_verification=not_run`, `patch_draft=null`, `requires_human_review=true`
фиксированы. Риск не пересчитывается объяснением. Сетевые последствия не
симулируются; готовые команды исправления не генерируются.

## Отчёт до/после

```powershell
.venv\Scripts\python.exe -m app.verification.preflight_cli --before previous.cfg --after candidate.cfg --device-id 7f64381c-fda8-48f9-8e8a-fb772b2f64dc --reference-id selected-v1 --explain
```

Без `--explain` сохраняется прежний формат preflight. С ним возвращается
объект `ExplainedPreflight`: исходный `report` и три отдельных списка:
`before_policy_explanations`, `after_policy_explanations`, `reference_explanations`.
Разделение сторон сохраняет корректную привязку строк к исходному или текущему
файлу. Коды возврата preflight не меняются. При неполном разборе доступные
политики объясняются, недоступное сравнение с эталоном остаётся недоступным.

JSON-отчёт содержит observed/expected из исходных находок и потому может
содержать сетевые адреса и имена объектов. Храните его закрыто. По умолчанию
модуль не обращается к внешним сервисам.

Тесты проверяют Cisco и JunOS, удаления/изменения BGP и VLAN, сохранение оценок,
раздельные anchors, модифицированные находки, неизвестные исходные команды
и режим CLI с частичным разбором. Проверка на реальных сетях не проводилась.
