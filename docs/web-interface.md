# Веб-интерфейс

React + TypeScript UI использует постоянный API без альтернативных детекторов
или фиктивных данных. Вход — настроенный service bearer-token. После подключения
доступны загрузка и история конфигураций, запуск policy-анализа с opt-in
сравнением с эталоном/peers, история результатов,
находки, строки-доказательства, hashes, объяснения, ограничения и оценки инженера.
Отдельный [экспериментальный config inference](configuration-model-inference.md)
с consent и immutable history не изменяет findings/risk; только engineer/admin
могут явно вызвать заранее выбранную оператором модель.
У выбранного снимка отдельно показано [измеренное покрытие строк](parser-coverage.md):
число принятых/неподдержанных строк и доля с явным знаменателем. Доверие парсера
не используется вместо подсчёта. Старый снимок без отчёта помечается как
неизмеренный; «принято адаптером» не означает проверенный синтаксис или безопасность.

## Запуск

Требуется Node.js 24 и установленный backend. Настройте БД, ключ шифрования и
токен по [инструкции API](persistent-api.md), выполните миграцию.
Из корня проекта:

```powershell
cd frontend
npm ci
npm run build
cd ..
uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/ui/`, введите свой `NETCONFIG_API_TOKEN`.
Root `/` перенаправляет на UI. Статика не содержит токен/ключ/данные пользователя;
все бизнес-операции по-прежнему требуют Authorization.
При входе UI проверяет [роль и permissions](service-roles.md); права без ответа
`GET /api/v1/session` не выдаются. Недоступные записи/обучение/model invocation
скрыты или отключены, но вся история остаётся доступной для чтения каждой роли.
Logout очищает permissions в памяти, не отзывает сам service key.
Если build отсутствует, `/ui/` возвращает явный 503, probes/API не ломаются.

Backend ищет `app/static` в пакете, затем локальный `frontend/dist`.
Для отдельного built directory можно явно задать `NETCONFIG_UI_DIR` в окружении
backend; указывайте только каталог публичной сборки, не корень проекта.
Сборка Python wheel после `npm run build` включает frontend assets через
[build hook](https://hatch.pypa.io/latest/plugins/build-hook/reference/).
Без предварительной UI-сборки Python package остаётся backend-only.

Для разработки в двух терминалах: backend на 8000, `npm run dev` из `frontend`;
UI доступен на `http://127.0.0.1:5173/ui/`. Vite
[проксирует API](https://vite.dev/config/server-options#server-proxy) только в
локальный backend. URL API пользователь не выбирает; CORS с wildcard не включается.
Production CSP применяется к built assets на backend, не к dev HMR.

`docker compose up --build` собирает frontend Node-stage, включает assets в
Python-stage, выполняет миграцию и запускает UI/API с PostgreSQL. Открывайте
тот же адрес `http://127.0.0.1:8000/ui/`. Секреты нужны только backend, не Vite build.

## Рабочий сценарий

1. Подключитесь service-токеном своей роли: сервер проверяет RBAC независимо от UI.
   Все роли читают общую историю; individual identity/tenant isolation не устанавливаются.
2. Для нового устройства используйте сгенерированный UUID. Для следующей версии
   выберите существующий снимок и нажмите «Использовать UUID устройства».
3. Выберите `.cfg`, `.conf` или `.txt` в UTF-8 либо вставьте текст. Бюджеты —
   2 MiB текста, 10000 строк и 3 MiB JSON-body. Filename без пути.
4. Сохраните снимок и запустите анализ. Каждый POST создаёт новую запись.
5. Изучите findings: severity, confidence и anomaly_score отображаются отдельно.
   Выберите находку или отфильтруйте по уровню ущерба/названию. Доказательства
   сохраняют исходные номера строк и hashes; для отсутствующего параметра
   строка не выдумывается.
6. В истории доступны страницы по 20 записей и фильтр выбранного устройства/снимка.
   После reload потребуется новый вход, но сохранённая история останется в БД.
7. В деталях находки выберите verdict, оставьте комментарий и сохраните оценку.
   Смена мнения добавляет запись, не заменяет прежнюю. История привязана к точному
   анализу и finding hash: [контракт и восстановление после сбоя](finding-feedback.md).
8. Для отдельного read-only просмотра выберите ранний снимок кнопкой «Выбрать
   для diff», затем следующий снимок того же устройства и «Показать различия
   объектов». Выбор не задаёт эталон анализа: [область и ограничения](snapshot-diff.md).
9. Сохраните различия как «Черновик объектов» и запустите локальную проверку.
   После повторного входа откройте поздний снимок, обновите черновики и выберите
   нужный отчёт: [история и повтор после сбоя](persistent-patches.md).
10. Для отдельного source-bound model candidate откройте «Модельные исправления»
    в находке. Явно разрешите generation, выберите retained network / scope,
    изучите review и сохраните engineer decision:
    [порядок работы и восстановление](model-patch-interface.md).

Текст файла очищается из формы после успешного сохранения. История возвращает
canonical snapshot, не original file. Неизвестные raw-фрагменты доступны отдельным
раскрываемым разделом; полный исходный файл для diff/Batfish не восстанавливается.

## Честная интерпретация

`partial` и неполный разбор явно выделены: итоговый риск недоступен, но частичные
находки показываются. Полностью разобранный текст — только поддерживаемая область
парсера, не полная проверка сети. Risk приходит от backend, не вычисляется UI.

Текущий HTTP-путь запускает политики и явно выбранные reference/peer comparisons.
Выбор снимков и метки группы описаны в [сравнениях API](api-comparisons.md).
Без явно выбранной модели ML помечен незапущенным. Доступны отдельный выбор
8–100 обучающих снимков, обучение и паспорт экспериментального Isolation Forest,
явный выбор модели и чтение ML-результата из истории:
[инструкция реестра](model-registry.md). Выбор очищается при выходе.
Transformer/Batfish не запускаются в исходном анализе. Отдельный candidate workflow
может выполнять их только при operator configuration и каждом явном request opt-in.
Объяснения локальные и детерминированные;
кнопка «Показать источники объяснения» извлекает конкретные разделы внутренней
документации с citations/hashes. LLM по умолчанию выключена, внешних вызовов и
семантического поиска нет: [контракт и ограничения](contextual-explanations.md).
При отдельной [настройке local transport](local-model-explanations.md) появляются
предупреждение о передаче и unchecked галочка; только её выбор разрешает кнопку
черновика модели. `configured` не означает проверенную доступность. Ответ модели
показан как непроверенный текст отдельно от исходного анализа; смена находки/logout
очищают ответ и разрешение. Работа конкретного adapter устанавливается отдельным
запросом, его успешный ответ не доказывает качество модели.
Схемы клиента отклоняют неизвестную версию, несогласованные IDs/hashes/оценки
и несоответствие анализа выбранному снимку вместо выдачи ложного результата.

Feedback не меняет исходный анализ/риск/модель, не удостоверяет личность автора
и не является проверенной меткой для обучения или согласованием патча.
Просмотр diff сравнивает нормализованные объекты, не исходные файлы; сохраняет
порядок ACL/rules и anchors соответствующей стороны. Unknown fragments исключены
с предупреждением partial; zero changes не является проверкой безопасности сети.
UI сохраняет нормализованные черновики и локальный preflight. Отдельная model-patch
панель отображает source-line edits, candidate-specific local/formal/ML results
и immutable reviewer decisions. Полный raw-file diff, hardware syntax/access test
и применение изменений не реализованы. Все существующие
offline preflight/patch инструменты сохраняются. Никакая кнопка не изменяет
конфигурацию на устройстве.

## Защита сессии

Токен хранится только в памяти текущей вкладки. Приложение не использует cookies,
localStorage, sessionStorage, Service Worker или внешний CDN. Нет поля внешнего
API URL. Redirect для API-запросов запрещён; ответ не кэшируется.

Logout/уход со страницы/возврат из page cache очищают сессию и результаты;
незавершённые fetch отменяются и запоздалые ответы игнорируются. Это не отмена
backend-транзакции. После 30-секундного таймаута проверьте историю перед повтором,
чтобы не создать дубликат. Browser extensions/сохранение паролей самим браузером
находятся вне контроля приложения.
Повтор feedback без изменения формы сохраняет прежний ID, поэтому сервер не
дублирует запись. ID живёт только в памяти формы; после её закрытия/reload
изучите историю до новой отправки. Изменённая оценка получает новый ID.
Черновик и локальная проверка также имеют IDs намерений в памяти формы;
неподтверждённый запрос повторяется с тем же ID. После подтверждённой проверки
следующая кнопка создаёт новый запуск. При смене снимка/reload сначала проверьте
сохранённую историю.

UI применяет [CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)
без unsafe-inline, no-store, no-referrer и запрет iframe. Конфигурационные значения
и citations показываются React-текстом, без HTML-инъекции и автоматически
открываемых untrusted ссылок. Подробнее — [модель угроз](threat-model.md).

## Проверки

```powershell
cd frontend
npm run typecheck
npm run format:check
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:model-patches
```

Browser tests запускают свежий loopback-only backend на 8301, создают временную
зашифрованную SQLite в игнорируемых artifacts и очищают её после завершения.
Они не используют рабочую БД или реальный токен разработчика; данные только тестовые.
Model-patch tests используют отдельную временную БД на 8302 и fixed synthetic
provider: [область доказательств](model-patch-interface.md). Это не реальная LLM
и не проверка её качества.
`NETCONFIG_TEST_PYTHON` позволяет явно выбрать Python executable; по умолчанию
Windows использует проектную `.venv`, Linux — `python` из PATH.

Desktop/mobile Chromium проверяет реальные API uploads Cisco/JunOS, историю после
reload, evidence, неполный parse, XSS-as-text, лимиты, неправильный токен,
disconnect during request и восстановление сессии.
Diff проверяет явную пару того же устройства, side-specific anchors, partial
JunOS, paging, отсутствие усечения, local rejection неверного reference,
response bindings, layout и игнорирование late response после logout.
Выбор эталона/трёх peers, совместный анализ и чтение его сохранённых inputs
проверяются отдельно; выбор текущего снимка как собственного эталона отклоняется.
Обучение, отдельный выбор модели, отказ анализировать обучающее устройство,
held-out scoring, очистка выбора и сохранённая ML-история проверяются в браузере.
Feedback проверяется на append-only history, неизменность анализа, изоляцию
между запусками, потерю ответа и идемпотентный повтор, восстановление из истории,
очистку черновиков и игнорирование запоздалых ответов после смены находки/logout.
Источники объяснения проверяются на точную привязку к анализу/находке, hashes
разделов, plain-text Markdown/HTML, partial parsing и очистку при смене/logout.
CI повторяет браузерный сценарий
против настоящего Compose backend/PostgreSQL. `NETCONFIG_E2E_BASE_URL` допустим
только для явного `http://127.0.0.1:<port>` с тестовым токеном; не указывайте рабочий API.

Admin имеет отдельный [журнал](operation-audit.md): роли/permissions/outcomes,
versions/hashes, keyset paging и явный неподтверждённый итог. Browser checks
проверяют недоступность для остальных ролей и неверную SHA-привязку.

Firefox/Safari, специализированный accessibility audit, TLS и production
нагрузка пока не проверены. Успех unit/browser tests не означает готовность всего MVP.

При загрузке есть отдельный [original retention opt-in](original-source-retention.md).
Checkbox default false, предупреждает о полных секретах; выбор действует только
для одной загрузки и сбрасывается после успеха/смены input. Raw-download UI нет.
