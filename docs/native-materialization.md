# Обычный черновик из сохранённого нативного кандидата

Реализован отдельный API/UI-сценарий с зашифрованной immutable историей.
Локальная приёмка подтверждает работу программы в описанных ниже границах;
она не является формальной проверкой изменения или оценкой независимого качества.

Для сохранённого нативного Telnet-кандидата предусмотрено отдельное действие:
создать снимок после изменения, его закрытый исходник и обычный object draft.
Новый снимок явно имеет происхождение `generated_native_candidate`.
Он не является наблюдением с устройства или одобренным baseline.

Перед действием требуются два отдельных согласия: на локальное создание снимка
и на сохранение полного закрытого текста кандидата. Текст может содержать
не связанные с изменением credentials. Удаление original-source строки не удаляет
другие ранее согласованные закрытые копии.

Для нового создания требуется retained original исходного снимка. Если его строка
удалена, действие возвращает `409`; закрытая копия в истории нативного кандидата
не используется для восстановления original. Сначала проверяются точные parent,
analysis, proof и source bindings. Локальный повторный разбор должен воспроизвести
исходную полную каноническую конфигурацию, а разбор кандидата — изменить только
поддержанную семантику `management.telnet_enabled: true → false`.
Declared inventory labels сохраняются. Поддержаны исходные schema 1.1 и 1.2;
schema 1.2 используется только в поддержанном Cisco-пути.

Снимок, retained source, обычный draft, generated-origin и четыре domain audit
события сохраняются одной транзакцией. Миграция `0019_native_materializations`
добавляет отдельную таблицу; старые записи и proofs не пересчитываются.
UUID выходного снимка и draft должны быть свободны. На одного нативного кандидата
сохраняется одна операция; тот же URL и intent возвращают первый результат,
а изменение intent даёт `409`.

Маршруты под `/api/v2/configurations/{configuration_id}/native-patches/{candidate_id}`:

- `POST /materialization` — явное создание с правом `draft`;
- `GET /materialization` — сохранённый результат с правом `read`.

`GET /api/v2/configurations/{after_configuration_id}/native-origin` возвращает
то же происхождение для входа через обычную историю снимков. Ошибка загрузки
происхождения остаётся неизвестным состоянием, а не признаком наблюдённых данных.
После `503` нужно проверить сохранённую историю и сохранять исходные UUID/intent
при повторе: результат мог быть записан до потери подтверждения.

Чтение и replay проверяют immutable proof и реальные сохранённые зависимости,
не запускают текущий parser, policy engine, генератор, ML или сетевой движок
и не требуют original-source строк. Public DTO и audit projection содержат
bounded metadata и hashes, не полный текст, raw diff или credentials.

Созданный объект остаётся обычным `draft`. Проверка политик через существующий
workflow — следующее отдельное явное действие. Материализация сама не выполняет
policy/model/network recheck и не переносит старые результаты на новый снимок.
`formal_qualification` остаётся `not_proven`, identity, approved и applied — false.
Локальный parser не подтверждает vendor syntax, доступ по SSH/AAA или свойства сети.
Подключение к устройствам и применение конфигураций не выполняются.

## Проверенный сценарий и ограничения

[Функциональный отчёт](evaluation/owned-native-materialization-functional.json)
содержит четыре финальных actual HTTP browser случая: две авторские семьи
Cisco/JunOS в двух размерах экрана. В каждом действительно выполнены генерация,
материализация и отдельная policy-only перепроверка, затем удаление исходной
source-row, смена процесса и точные GET/origin/replay без runtime-доступа.
Повторы, подготовки и размеры экрана не увеличивают независимый корпус.
Model inference, network engine и fit в этих четырёх случаях не запускались.

Полный локальный Python-набор: 5602 pass / 76 skip, coverage 92%.
Извлечённый wheel с точными 325 runtime-файлами, тремя UI-assets и 36 knowledge
файлами: 1867 pass / 58 skip на каждой Pydantic 2.13.5, 2.14.0 и 2.14.1.
UI: 1014 unit / 430 browser, включая 16 новых mock и четыре новых actual случая.
Ruff, mypy, typecheck, build и format прошли; backend/UI проверены независимо.
Шестнадцать новых PostgreSQL opt-in случаев локально skipped: тестовая БД
не выбрана. CI конкретной публикуемой версии проверяется отдельно после публикации.

Проверены гонки одинакового/разного intent, коллизии выходных UUID, rollback
восьми границ row/audit, повреждения saved dependencies и populated upgrade18→19.
Ранее упавшие миграционные подготовки и прерванные прогоны сохранены отдельно;
после исправления проверены те же условия сохранности старых строк.
Выбор другого обычного черновика сохраняется при внешнем busy/503; кнопка
происхождения открывает связанный draft только по новому явному действию.
