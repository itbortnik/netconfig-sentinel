# Наблюдения точек входа и адресов источника

Новая сетевая проверка сохранённых исходников явно использует
`source-patch-request-0.4.0`. Она сохраняет прежний результат достижимости,
направление возвращённых примеров и отдельное `ingress_scope` в
`batfish-execution-0.4.0`. Это описание выбранной области проверки; охват flows
не расширяется. Удалённые точки входа не становятся проверенными flows.

В том же изолированном worker выполняются до шести дополнительных логических
вопросов: выбранные locations, свойства интерфейсов и вывод адресов источника
для before и after. Они используют те же snapshots, временную сеть и общий
deadline. Начальный узел передаётся как quoted literal. Значения из конфигурации
не становятся выражением выбора другого узла.

| Состояние | Сохранённые сведения |
| --- | --- |
| `observed` / `query_completed` | Обе полные ограниченные таблицы и проверенные производные поля. Пригодность отдельных интерфейсов может оставаться неизвестной. |
| `unknown` | Причина ошибки вопроса, неподдержанной формы, неполного назначения, превышения бюджета или неподтверждённой очистки; обе таблицы и производные наборы `null`. |
| `not_observed` / `not_run` | Базовая сетевая проверка не дошла до сбора наблюдений. Это отсутствие результата, без нулей или предполагаемых интерфейсов. |

Вопросы наблюдения не заменяют ошибки базовой проверки успешным результатом.
Их собственная ошибка сохраняет уже полученные reachability evidence и направление;
общий timeout worker сохраняет прежнюю семантику timeout. Неподтверждённая очистка
не позволяет сохранять наблюдение как завершённое.

Для поддержанного `InterfaceLocation` сохраняются точные node/interface,
версионированный SHA-256 идентичности, исходное rendering location, modeled `Active`,
тип, `Switchport`, конкретные IPv4 prefixes с host bits и rendering адресов источника
с его SHA-256. Rendering IP-space остаётся непрозрачной строкой. Строки `empty`
и `EmptyIpSpace` не интерпретируются как доказательство пустого математического множества.

Пригодность в ограниченном методе имеет три значения:

- `true`: modeled active, не switchport, есть конкретный IPv4 prefix;
- `false`: modeled inactive или switchport;
- `null`: нет конкретного IPv4 prefix, поэтому пригодность неизвестна.

Например, JunOS physical parent без IPv4 остаётся неизвестным, даже если его logical
unit имеет адрес. `Active` не удостоверяет фактическое состояние канала. Метод не
интерпретирует произвольные другие виды locations или символические IP spaces.

Различия выбранных идентичностей можно сохранить при неизвестной пригодности.
Общие/исключённые пригодные идентичности и назначения адресов для общих интерфейсов
сохраняются только при полной известности обеих сторон. Иначе эти поля `null`;
частичный список не выдаётся за полный. Before/after строки относятся к своей стороне,
`after_common_assignments` — только к контексту after. Равенство SHA строки не
доказывает равенство IP-множеств. `semantic_ip_sets_verified` и
`complete_flow_coverage` всегда strict false.

Бюджеты допуска:256 строк на сторону,64 IPv4 prefixes на интерфейс,4096 UTF-8 bytes
на IP rendering,65536 bytes на итоговое наблюдение,262144 bytes на raw answer
и worker output. Лимиты admission проверяются после получения SDK ответа; они не
являются жёсткой границей памяти при HTTP download.

Совместный request/report0.4 сохраняет точную проекцию выбранного child, включая
наблюдения, SDK metadata и направление. Decision0.4 привязывается только к report0.4.
Отдельная risk request/assessment0.2 и composition0.2 сохраняют полную execution0.4;
арифметический профиль остаётся `source-priority-profile-0.1.0`. Неизвестная область
не отменяет уже наблюдённую потерю: ограничитель приоритета0.95 сохраняется.
Nonloss/unknown не превращаются в безопасный сетевой ноль.

Новые записи используют прежние encrypted tables и atomic audit без новой миграции.
GET/list/idempotent replay проверяют сохранённую цепочку без SDK или исходных текстов.
Старые source/report/decision0.1–0.3, risk0.1 и их proofs не переписываются.
Новый report может явно выбрать старый child; старый report отказывает новому child
с409. Историческая несовместимость считается повреждением и возвращает503.
Интерфейс создаёт новые source/report0.4, выбирает decision по версии parent и
risk0.2 для report0.4. Старые записи читаются в исходной версии.

Общий formal остаётся `not_proven`. Management/SSH/AAA, IPv6, внешняя доставка,
vendor syntax, вся topology и operational state этим не квалифицированы.
Модельное качество, калибровка, индивидуальная личность, approval и применение
не устанавливаются. MVP не применяет изменения автоматически.

[Фактический HTTP-прогон](evaluation/owned-source-ingress-functional.json) повторно
использовал две прежние authored пары и шесть сохранённых detector/model outputs.
Выполнены два новых SDK calls, сохранены два joint reports, четыре отдельные оценки
и восемь решений сервисных ролей. Новых model calls/fits нет. Полные привязки,
неизменность прежних физических строк и replay после удаления originals/models/
двух references проверены на копии БД. Оба scoped результата не вернули witnesses;
это не подтверждает неизменность всех flows или качество на реальных сетях.
